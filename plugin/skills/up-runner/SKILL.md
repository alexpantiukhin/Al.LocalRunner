# up-runner

Inputs: the runner settings file (default: one general runner) and the number of copies (`--count`, default 1).

1. If `localrunner` is not installed, run `install-runner` first. Read `../../shared/os/<windows|linux|macos>.md` for the current OS.
2. A runner with its own settings or several copies is created once: `localrunner runner join <host:port> --code-file <file> --config <runner.toml> --count N --name <name>`. The code comes from `localrunner broker add` on the broker. Pass it with `--code-file` (`-` is standard input) or `LOCALRUNNER_JOIN_CODE`; avoid the command line, other local users see it. Never print or store the code. If `broker add` is refused because the broker is an OS service (its admin channel is open only to an administrator, on Unix to the broker's OS user) and `join` refuses an administrator, ask the user whether they are ready to confirm the elevation prompt (UAC or `sudo`), name what will run and wait for the answer: `localrunner broker add --runners N --code-file <file>`, with `<file>` in a new private directory (the file must not exist). Run only that command elevated, then `runner join` as the ordinary user, and delete the file and its directory at once, also when the join fails.
3. A client machine (a hub) joins the broker with a code from `localrunner broker add --name <name> --label <label>`: the label of a client is unique, a taken one is refused. The broker owner may join clients and runners that reach one disk with `localrunner policy add-shared <member> <member>` (client labels and runner names; `localrunner policy remove-shared <member> <member>` takes the block back); the zone between them is then `shared`. The command prints the diff (`--dry-run` writes nothing) and the broker takes the block on reload; for a broker that runs as an OS service it reruns itself elevated: ask first whether the user is ready to confirm the UAC or `sudo` prompt and wait for the answer.
4. `localrunner up` starts every role that `init` created, each as a background process, in the order broker, hub, runners. `localrunner up <names>` takes the names of `down`: `hub`, `broker`, `runner` (every runner) or one runner by its name (`<name>` or `local:<name>`, as `localrunner runners` prints it); `up runner` also starts runners that were stopped on purpose, so to bring back one runner after changing its `runner.toml` name it. An unknown name is an error that lists the names of this installation. Running roles are not duplicated. Do not add another detaching wrapper.
5. A broker installed as an OS service is not started by `up`: start it with the service manager. The same holds for a runner installed as an OS service: `up` never starts a second copy and, when the service is stopped, prints the start command for an administrator and returns 1. If `up` returns 1, report the reason it printed. If it says an upgrade runs (`upgrade.lock`, with the PID of `localrunner upgrade`), do not repeat `up` and do not start runners another way: wait until the upgrade ends, then check `localrunner status`. A runner refused because it would run under the OS user of a broker that admits other clients (spec 3.12) is reported to the user as is; never turn on `allow_same_user_as_broker` on your own: that is the owner's explicit decision.
6. Finish with `status-runner`; `localrunner runners` shows whether the runners reported in.
