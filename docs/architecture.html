Al.LocalRunner — архитектура

Очередь запусков тестов и сборок на нескольких машинах. Документ описывает, как система устроена: окружение, компоненты, данные и потоки. Источники: docs/design.md (что должно быть) и docs/superpowers/plans/2026-11-09-localrunner.md (как строится).

1. Принципы

  • Универсальное ядро. Очередь, планировщик и демон не знают про язык, тестовый фреймворк и платформы. Названия платформ, метки и команды приходят от владельца машины и из профилей проекта.
  • Один бинарник, три роли. al-localrunner работает как hub (очередь, планировщик, дашборд), раннер (выполняет джобы) и клиент (отправляет и смотрит). По умолчанию каждая машина сама себе hub.
  • Раннер сам подключается к hub, как у GitHub self-hosted: входящие порты на раннере не нужны.
  • Ресурсы считаются по пулу (физической или виртуальной машине), а не по раннеру. Docker-раннер на Windows входит в пул хоста.
  • Локальный раннер тестирует рабочее дерево, удалённый — запушенный коммит.
  • Ничего не уходит наружу. Дашборд слушает только loopback; телеметрии и загрузок нет.

2. Архитектура: машины и связи

Этап 1 — всё в одной локальной сети. Раннеры на VPS и за чужим роутером — следующий этап; схема им не мешает.

Синие стрелки — постоянное TLS-соединение раннера или клиента к hub (протокол с проверкой версии, heartbeat 15 с). Серые — локальный IPC, HTTP на loopback и git. Зелёные рамки — раннеры, все они подчиняются одному hub.

Ключевые решения

  • Hub выбирает пользователь; по умолчанию это машина, с которой он работает. Любая другая машина тоже может быть hub. Несколько клиентов на одном hub дают общую очередь, раздельные hub — раздельные очереди.
  • Раннер выбирается по порядку: сначала подходящий по уровню, платформе, меткам и ресурсам; среди подходящих — ближайший по зоне (local, затем lan, затем remote). Зона считается относительно отправителя через метку network.
  • Приоритет у ci, без вытеснения запущенных; джоб без ci, который ждёт больше 30 минут, упорядочивается как ci.
  • Если hub пропал на 10 минут, раннер убивает свои запущенные джобы; результаты завершённых хранит и отдаёт позже.

4. Данные

Две базы SQLite. history.db есть на каждой машине и хранит джобы, выполненные на ней. hub.db есть только у hub и хранит реестр машин, пулы, раннеры, очередь и аренды. Связи между базами логические, по идентификаторам: внешних ключей между файлами нет. Полные логи лежат файлами в logs/<job-id>.log.

  • Финальное состояние джоба пишется один раз: повторная доставка результата или второе конечное состояние не меняют строку.
  • Удалённый джоб записывается в history.db машины раннера; hub держит только queue_entry до старта и аренды lease.
  • Хранение: логи 30 дней и 2 ГБ, строки 365 дней; чистка идёт с самых старых и не трогает активные джобы.
  • В machine хранятся только публичные ключи; токен регистрации ci-раннера не пишется никуда.

6. Потоки

Локальный запуск

  1. CLI собирает идентичность (--as, пользователь ОС, ветка, проект) и читает профиль из рабочего дерева.
  2. По IPC уходит Submit; движок отклоняет джоб, который не поместится в пул, и ограничивает таймаут сверху.
  3. pick_next выбирает локальный раннер; планировщик выдаёт память, процессор и метки пула.
  4. run_job выполняет шаги в каталоге отправителя; вывод идёт в лог, в temp/runner/<id>.log и в шину событий.
  5. Результат пишется в history.db; ресурсы освобождаются только после того, как дерево процессов мертво.

Удалённый запуск на другой платформе

  1. CLI проверяет, что HEAD запушен (иначе просит закоммитить и запушить ветку без MR), читает профиль из коммита.
  2. На каждую платформу создаётся джоб в одной группе; команды берутся из platform.<имя>.
  3. pick_next отбирает раннеры по уровню, платформе, меткам и ресурсам пула, затем выбирает ближайшую зону.
  4. Hub шлёт Assign по TLS-каналу; раннер делает git fetch и чистый отсоединённый checkout.
  5. Раннер стримит Chunk с номером seq и пишет итог у себя; hub подтверждает Ack и ретранслирует вывод CLI и дашборду.
  6. После обрыва связи раннер повторяет неподтверждённое из Outbox; hub отбрасывает дубликаты по seq.
